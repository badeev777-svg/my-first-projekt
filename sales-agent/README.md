# sales-agent — AI-помощник по продажам Badeev Agency

Чат-помощник для сайта. Он выясняет задачу клиента, подбирает услугу из каталога, называет только утверждённые цены, а при согласии клиента оформляет заявку и передаёт разговор человеку.

Заявки и передачи человеку приходят менеджеру в Telegram, если в `.env` заданы `NOTIFY_BOT_TOKEN` и `NOTIFY_CHAT_ID`; без них — в канал-заглушку (только лог).

## Запуск

1. Один раз установите [uv](https://docs.astral.sh/uv/).
2. Дважды щёлкните `start.bat`. Откроется браузер с чатом: http://127.0.0.1:8000/
3. Остановить — закрыть чёрное окно или нажать `Ctrl+C`.

## Режимы

| Режим | Когда | Что происходит |
|---|---|---|
| **DEMO** | в `.env` пустой `CLOUDRU_API_KEY` | модель не вызывается, бот отвечает шаблоном, на странице плашка DEMO |
| **Рабочий** | ключ cloud.ru указан в `.env` | отвечает GigaChat-2-Max через cloud.ru |

Ключ вписывается только в файл `.env` рядом с `start.bat`, в строку `CLOUDRU_API_KEY=`. Не отправляйте ключ в чаты и письма. Файл `.env` в git не попадает.

## Каталог — правится без программиста

Все данные лежат в папке `content/`:

| Файл | Что внутри |
|---|---|
| `services.yaml` | услуги и цены |
| `projects.yaml` | проекты-примеры и их статус |
| `faq.yaml` | частые вопросы |
| `policy.yaml` | тон, кому уходят заявки, текст согласия |
| `role.md` | кем представляется бот |

Главное правило: **бот называет цену только у услуги с `approved: true`**. Изменили цену — перезапустите `start.bat`.

При `consent_approved: true` в `policy.yaml` (текст согласия утверждён 2026-10-17) полный контакт хранится в заявке и уходит менеджеру в Telegram. При `false` заявка демо: телефон не хранится и не отправляется.

## Заявки

Откройте http://127.0.0.1:8000/admin — **только на этом же компьютере**. С других адресов админка не открывается. Там видны заявки, передачи человеку и диалоги, которые ждут ответа. Кнопка «Вернуть боту» снова включает автоответы в диалоге.

> ⚠️ За обратным прокси (nginx и т.п.) на этом же сервере админка может стать публичной: прокси подключается с 127.0.0.1. Так не разворачивайте без отдельной защиты админки.

## Проверки

- `uv run pytest` — автотесты, включая 14 сценариев из ТЗ.
- `uv run python scripts/live_acceptance.py` — живой прогон на GigaChat (нужен ключ, тратит токены cloud.ru). Итог — в `docs/acceptance-report.md`.

## Docker (упаковка, не деплой)

Сначала скопируйте `.env.example` в `.env` (и при желании впишите ключ), затем `docker compose up -d --build` — чат на http://127.0.0.1:8092/. Админка в Docker недоступна (403): адрес запроса там не локальный — ожидаемо, не проверено: Docker не установлен.

## Бот в MAX

Если в `.env` заданы `MAX_BOT_TOKEN` и `MAX_WEBHOOK_SECRET`, тот же помощник отвечает в личных сообщениях бота MAX через вебхук `POST /api/max/webhook`. Секрет MAX присылает в заголовке `X-Max-Bot-Api-Secret`; без него запрос отклоняется (403), без настроек вебхук отвечает 404. Подписка вебхука делается один раз запросом `POST https://platform-api2.max.ru/subscriptions`. «Начать заново» или `/new` открывают новый диалог. Форма входящих апдейтов взята из документации MAX и на живом боте ещё не проверена.

## Чего нет в этой версии

Работы бота в Telegram/Avito, ответа менеджера клиенту из админки, CRM, оплаты, рассылок. Каждое из этого подключается отдельным решением.
