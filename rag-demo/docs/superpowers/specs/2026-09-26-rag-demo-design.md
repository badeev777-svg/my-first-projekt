# RAG-демо «Ответы по документам компании» — дизайн

**Дата:** 2026-09-26
**Статус:** дизайн утверждён в чате, ожидает ревью спецификации

## 1. Цель

Живое демо для встреч с клиентами: клиент загружает свои PDF/DOCX в браузере, задаёт вопросы и получает ответы строго по документам со ссылкой на файл и страницу.

Бизнес-задача: закрыть пробел «RAG» в портфеле услуг (см. сравнение с пакетами интеграторов от 150–349 тыс. ₽ в `memory/2026-09-26.md`) и получить инструмент продаж.

## 2. Решения (утверждены пользователем)

| Вопрос | Решение |
|---|---|
| Назначение | Показ клиентам на встрече, с их файлами |
| Интерфейс | Веб-страница (браузер) |
| Форматы v1 | PDF и DOCX с текстовым слоем |
| Данные клиента | Временная сессия, автоудаление через 1 час, без входа по логину |
| Архитектура | Свой сервис (FastAPI) + модели cloud.ru Foundation Models |
| Сервер / домен | VPS 155.212.208.194, `rag.бизнесгенератор.рф` |

## 3. Проверенные факты о моделях (2026-09-26)

Получено запросом `GET https://foundation-models.api.cloud.ru/v1/models` с существующим ключом из lead-parser и по документации cloud.ru (overview__available__models):

- Эмбеддинги: `BAAI/bge-m3` (выбрана), альтернатива `Qwen/Qwen3-Embedding-0.6B`
- Реранкер: `BAAI/bge-reranker-v2-m3`
- Генерация: `ai-sage/GigaChat3.5-432B-A28B` (по умолчанию), альтернатива `GigaChat/GigaChat-2-Max`
- Все перечисленные cloud.ru помечает как **внутренние** («без передачи данных во внешние системы»).

**Не подтверждено:** географическое размещение инфраструктуры cloud.ru в РФ. До использования формулировки «данные в РФ / 152-ФЗ» в продажах — подтвердить по документам/договору cloud.ru или через поддержку.

**Не проверено:** формат ответа реранкера в API cloud.ru (эндпоинт и схема) — проверить первым шагом реализации; цены на эмбеддинги/реранкер — посчитать на живом тесте.

## 4. Архитектура

Папка: `my-first-projekt/rag-demo/`. Python, FastAPI, pytest.

| Модуль | Ответственность |
|---|---|
| `app/extract.py` | Текст из PDF (с номерами страниц) и DOCX (с номером абзаца/раздела) |
| `app/chunker.py` | Нарезка ~800 символов с перекрытием; метаданные: файл, страница |
| `app/cloudru.py` | Клиент cloud.ru: `embed()`, `rerank()`, `chat()`; ключ, таймауты, 1 повтор |
| `app/session_store.py` | Сессии в памяти: куски, векторы, время создания; удаление старше 1 ч |
| `app/rag.py` | Вопрос → embed → косинусный поиск топ-20 → rerank топ-5 → GigaChat с источниками |
| `app/main.py` | FastAPI: `POST /upload`, `POST /ask`, `DELETE /session`, статика |
| `static/index.html` | Одна страница: загрузка слева, чат справа, ввод кода доступа |

### Поток данных

```
Загрузка: файл → extract → chunker → embed → session_store (RAM)
Вопрос:   вопрос → embed → поиск по векторам → rerank → chat → ответ + [файл, стр. N]
Очистка:  фоновая задача каждые 5 мин удаляет сессии старше 1 ч; кнопка «Удалить мои данные»
```

### Правило «без выдумок»

Системный промпт требует отвечать только по переданным фрагментам. Если ответа в них нет — ответ «В загруженных документах этого нет». Каждое утверждение сопровождается ссылкой `[файл, стр. N]`; клик показывает цитируемый фрагмент.

## 5. Ограничения (стартовые значения, пересмотреть после замера стоимости)

- До 10 файлов на сессию, до 20 МБ на файл
- До 60 вопросов на сессию
- Доступ по коду (`ACCESS_CODE` в `.env`)

## 6. Ошибки

| Ситуация | Сообщение пользователю |
|---|---|
| PDF без текстового слоя | «Похоже, это скан. Распознавание сканов появится в следующей версии.» |
| Не PDF/DOCX | «Поддерживаются PDF и DOCX.» |
| cloud.ru недоступен (после 1 повтора) | «Сервис ИИ временно недоступен, попробуйте через минуту.» |
| Сессия истекла | «Сессия завершена, документы удалены. Загрузите их снова.» |
| Превышен лимит | Сообщение с конкретным лимитом |

## 7. Безопасность

- Файлы не пишутся на диск: обработка в памяти
- Содержимое документов и вопросов не логируется, только технические события
- Ключ cloud.ru и код доступа только в `.env` на сервере, `.env` в `.gitignore`
- Сессия — случайный идентификатор в HttpOnly cookie
- Только HTTPS

## 8. Тестирование

- Unit (TDD): extract, chunker, session_store, rag с замоканным `cloudru`
- Живой smoke-тест с реальным ключом: загрузка → вопрос → ответ со ссылкой
- Приёмка качества: 2–3 вымышленных документа (регламент, прайс, договор) + 10 контрольных вопросов, из них 3 без ответа в документах. Критерий: верные ответы со ссылками; на 3 «пустых» вопроса — «этого нет». Эти документы же — демо-набор по умолчанию.
