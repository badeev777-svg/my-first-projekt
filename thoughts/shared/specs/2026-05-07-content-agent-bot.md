# Content Agent Bot — Спецификация для разработки

**Дата:** 2026-05-07  
**Статус:** Готово к разработке  
**Модель для разработки:** Claude Opus  
**Стек:** Python + Telegram Bot + Claude Opus API + PostgreSQL + VPS

---

## Executive Summary

Telegram-бот с мультиагентной архитектурой для генерации контент-планов на неделю.  
Пользователь вставляет URL любого публичного сайта или статьи конкурента → бот анализирует контент, строит стратегическую воронку и генерирует посты под выбранные платформы **в личном стиле пользователя**.  
Целевая аудитория: маркетологи, копирайтеры, SMM-специалисты. Монетизация: freemium (3 бесплатные генерации → подписка 499 ₽/мес).

---

## Проблема

SMM-специалист тратит часы на написание постов. Существующие инструменты:
- Либо не поддерживают русскоязычные платформы (Telegram, ВКонтакте, VC.ru)
- Либо генерируют generic-контент без учёта личного стиля
- Либо требуют переключения между десятком вкладок

**Незанятая ниша:** «URL конкурента → недельный план постов в моём стиле для TG + VK + Сторис + VC.ru» прямо в Telegram — такого продукта на рынке нет.

---

## Критерии успеха (MVP)

- Пользователь получает недельный план за **< 3 минут**
- ≥ 5 из 7 постов используются без существенной правки
- Пользователь возвращается на следующей неделе (retention)
- Конверсия free → paid ≥ 15%

---

## Целевая аудитория

**Основная:** Маркетолог / SMM-фрилансер  
- Ведёт 3–10 клиентов одновременно  
- Технически грамотен, работает в Telegram ежедневно  
- Боль: нет времени часами вымучивать тексты  

**Вторичная:** Инхаус SMM-специалист  
- Ведёт один бренд, нужен устойчивый стиль и постоянство публикаций

## Пользовательский сценарий

### Первый запуск (онбординг)

```
1. /start
   → Приветствие + объяснение механики

2. Онбординг-анкета (5 вопросов):
   - Ниша/тематика: «О чём пишешь?»
   - Тон: [Экспертный] [Дружеский] [Провокационный]
   - Табу: «Что никогда не пишешь?»
   - Любимые форматы: [Списки] [Истории] [Факты] [Кейсы] (мультивыбор)
   - Примеры постов: «Пришли 1–3 своих лучших поста» [Пропустить]

3. Профиль сохранён
   → «Готово! Теперь вставляй URL для анализа.»
```

### Генерация недельного плана

```
1. Пользователь вставляет URL (любая публичная веб-страница)

2. Бот: «Анализирую контент...» (индикатор прогресса)
   → Агент-аналитик скрейпит и извлекает тезисы

3. Бот показывает чекбоксы платформ:
   [✅] Telegram-канал
   [✅] ВКонтакте
   [✅] Сторис
   [ ] VC.ru (структура статьи)

4. Бот: «Строю стратегию недели...»
   → Агент-стратег формирует воронку по дням

5. Бот отправляет посты по одному:
   📅 День 1 · Telegram
   [текст поста]
   #хэштег1 #хэштег2
   ⏰ Лучшее время: 10:00
   [🔄 Переписать] [✂️ Короче] [👔 Формальнее] [👍 Нравится]

6. После всех постов:
   [📋 Весь план одним текстом] [📁 Сохранить в историю]
```

### Управление стилем

```
/style          → показывает текущий профиль
/style edit     → редактирование анкеты
/examples       → загрузка примеров постов для уточнения стиля
/history        → последние 5 сохранённых планов
```

## Функциональные требования

### P0 — MVP (разрабатывается первым)

#### Система памяти и стиля пользователя

- Профиль пользователя сохраняется в БД при онбординге
- При каждой генерации профиль **инжектируется в системный промпт** всех агентов
- `/style` — просмотр профиля
- `/style edit` — повторное прохождение анкеты
- `/examples` — пользователь присылает текст → агент-аналитик извлекает паттерны стиля → обновляет профиль

#### Скрейпинг контента

- Принимает любые публичные веб-страницы
- Основной метод: `httpx` + `BeautifulSoup4`
- Fallback для JS-heavy страниц: `Playwright`
- Что извлекается: заголовок, ключевые тезисы (до 5), тональность источника, основная тема
- Если URL недоступен → понятное сообщение об ошибке + предложение попробовать другой URL

#### Мультиагентная генерация

| Агент | Задача | Input | Output |
|---|---|---|---|
| **Scraper Agent** | Анализ URL | URL | JSON: тезисы, тема, тон |
| **Strategist Agent** | Структура недели | Тезисы + профиль | 7-дневный план с типами постов |
| **Copywriter Agent × платформа** | Написание текста | Angle + тип + профиль + платформа | Готовый пост |

#### Стратегическая воронка (Strategist Agent)

```
День 1–2: Вовлечение (вопрос, провокация, неожиданный факт)
День 3–4: Экспертиза (кейс, разбор, инструкция)
День 5–6: Доверие (история, результат, отзыв)
День 7:   Продажа (оффер, CTA, выгода)
```

#### Промпты под каждую платформу

| Платформа | Формат | Особенности |
|---|---|---|
| **Telegram** | 150–400 слов | Личный голос, без корпоратизма, Bold/Italic, 3–5 хэштегов |
| **ВКонтакте** | 200–500 слов | Развёрнуто, эмодзи, хэштеги, CTA на подписку |
| **Сторис** | 5 слайдов | Краткие фразы (3–7 слов/слайд), эмодзи, визуальный крючок |
| **VC.ru** | Структура статьи | Заголовок + крюк + 3–4 раздела с тезисами + вывод + CTA |

Каждый пост содержит: **текст + хэштеги + CTA + рекомендованное время публикации**

#### Монетизация

- 3 бесплатных полных генерации (каждый недельный план = 1 генерация)
- После исчерпания → предложение подписки **499 ₽/мес**
- Блокировка генерации без активной подписки
- Платёжная система: **Telegram Payments API** (MVP)

#### UX / Telegram-интерфейс

- Каждый пост — отдельное сообщение (для удобного копирования)
- Кнопки под каждым постом: [🔄 Переписать] [✂️ Короче] [👔 Формальнее] [👍 Нравится]
- Индикаторы прогресса при длинных операциях (`typing...`)
- `/history` — последние 5 планов с возможностью открыть любой
- Весь план одним текстовым блоком по запросу

## Техническая архитектура

### Стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.11+ |
| Telegram Bot | `python-telegram-bot` v20+ (async) |
| LLM | Claude Opus (`claude-opus-4-5`) via Anthropic SDK |
| Prompt Caching | Anthropic Prompt Caching для системных промптов (снижение затрат) |
| Скрейпинг | `httpx` + `BeautifulSoup4`, fallback `Playwright` |
| База данных | PostgreSQL + `SQLAlchemy` (async) + `Alembic` (миграции) |
| Очередь задач | `asyncio` + PostgreSQL advisory locks (MVP), при росте → Celery |
| Хостинг | VPS, `Docker` + `docker-compose` |
| Платежи | Telegram Payments API |

### Схема данных

```sql
-- Пользователь
User {
  telegram_id     BIGINT PRIMARY KEY,
  username        TEXT,
  created_at      TIMESTAMP,
  subscription    ENUM('free', 'paid'),
  gens_used       INT DEFAULT 0,
  sub_expires     TIMESTAMP NULL
}

-- Профиль стиля
UserProfile {
  user_id         BIGINT FK -> User,
  niche           TEXT,             -- «О чём пишешь»
  tone            ENUM('expert', 'friendly', 'provocative'),
  forbidden       TEXT[],           -- запрещённые темы
  formats         TEXT[],           -- любимые форматы
  example_posts   TEXT[],           -- примеры постов пользователя
  style_notes     TEXT,             -- авто-извлечённые паттерны стиля
  updated_at      TIMESTAMP
}

-- Контент-план
ContentPlan {
  id              UUID PRIMARY KEY,
  user_id         BIGINT FK -> User,
  source_url      TEXT,
  source_summary  TEXT,             -- что извлёк Scraper Agent
  platforms       TEXT[],
  created_at      TIMESTAMP
}

-- Пост
Post {
  id              UUID PRIMARY KEY,
  plan_id         UUID FK -> ContentPlan,
  day             INT,              -- 1-7
  platform        ENUM('telegram', 'vk', 'stories', 'vc_ru'),
  post_type       ENUM('engagement', 'expertise', 'trust', 'sale'),
  content         TEXT,
  hashtags        TEXT[],
  cta             TEXT,
  rec_time        TEXT,             -- «10:00», «19:00»
  feedback        ENUM('liked', 'rewritten', 'none') DEFAULT 'none'
}
```

### Архитектура агентов

```
User → Telegram Bot
           │
           ▼
    [Scraper Agent]
    httpx / Playwright
    → извлекает тезисы из URL
           │
           ▼
    [Strategist Agent]
    Claude Opus
    Знает: тезисы + профиль пользователя
    → строит 7-дневную воронку
           │
    ┌──────┴──────┬──────────────┐
    ▼             ▼              ▼
[TG Agent]  [VK Agent]   [Stories Agent]  [VC.ru Agent]
Claude Opus × отдельный системный промпт на каждую платформу
Знает: angle + тип дня + профиль + платформа
    │
    ▼
  Посты → Telegram (по одному сообщению)
```

### Prompt Caching (важно для экономии)

Системные промпты для каждой платформы **не меняются** между запросами — их нужно кэшировать через Anthropic Prompt Caching. Профиль пользователя добавляется в user-часть промпта (не кэшируется, так как уникален).

### Rate Limiting

- Максимум 1 генерация в час на пользователя (защита от спама)
- Максимум 3 нажатия «Переписать» на пост (снижение затрат)
- Timeout на скрейпинг: 15 секунд

---

## Безопасность

- Идентификация только по `telegram_id` — нет email, нет пароля
- API ключи через переменные окружения (`.env` + Docker secrets)
- Профили хранятся только в PostgreSQL, не в памяти процесса
- Входящие URL валидируются (только `http://` и `https://`, блокировка локальных адресов)
- Защита от SSRF: whitelist схем, blacklist приватных диапазонов IP

## Открытые вопросы для реализации

1. **Playwright в MVP?** Большинство сайтов работают с `httpx`. Playwright добавляет 200+ МБ. Рекомендация: начать с `httpx`, добавить Playwright как optional dependency при необходимости.

2. **Платёжная система:** Telegram Payments API (самый простой путь для MVP) vs YooKassa (больше контроля, но сложнее). Рекомендация: Telegram Payments для MVP.

3. **Очередь задач:** `asyncio` + PostgreSQL locks достаточно для < 1000 пользователей. При росте — Celery + Redis.

4. **Промпт-кэширование:** Обязательно реализовать с первой версии. Без кэширования при 100 пользователях/день расходы на API Claude Opus будут в 3–4 раза выше.

5. **Scraper Agent vs прямой вызов:** Для простых URL достаточно прямого вызова httpx в основном коде. Отдельный «агент» нужен только если требуется JavaScript-рендеринг.
